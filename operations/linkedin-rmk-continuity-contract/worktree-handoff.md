## Release handoff protocol

Each future consumer `binding.json` records: row/entry IDs; contract release ID + release-manifest SHA256; case content revision; claim IDs; locale readiness; exact public promise fields; logical destination; final artifacts/hashes; and its own branch + commit. Uncommitted drafts are labeled as such and cannot be final acceptance inputs. No runtime request consults Git: the bound release must be packaged with the artifact.

For a new shared release, coordinator records old/new release IDs, exact changed fields, affected entries/locales/artifacts, evidence reason and required rechecks. Each writer explicitly acknowledges the new manifest SHA in its updated binding. Old outputs stay pinned to the old release; mismatch blocks acceptance. A changed case fans out to every entry using it. The LDP does not silently redirect an old accepted entry to revised content. Version handling must serve the exact supported published release or show an explicit unavailable state; a version label alone cannot mask new bytes.
