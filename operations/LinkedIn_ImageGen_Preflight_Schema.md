## Implemented v1 wire format and operation

All JSON objects reject unknown fields and duplicate keys. Schema version is integer `1`; revisions are nonempty strings. References have exactly `{path, sha256, revision}` with lower-case SHA-256 of saved bytes. Paths are repo-relative and resolved inside the selected root; missing/mutated inputs fail. The coordinator supplies `--release` and its independently recorded `--release-sha256`; the call writer cannot choose a replacement through the spec. | Campaign contract | `schema_version, revision, locale, channel, copy, sources, card_sources, ad_order, card_order, surfaces, definitions, limits, groups, reuse_fields, references, style, output`. Initial whole-batch preflight protects every output; fresh per-call preflight with `--call-id` and dispatch protect the selected output while allowing completed siblings. Viewer-copy checks do not require artwork outputs to be absent. Dimensions are planned requirements, not assertions about nonexistent generated files. |
| Source/copy review | `schema_version, revision, writer, reviewer, date, scope, independence, subjects, verdicts, reviewed_ads, reviewed_fields, unresolved_findings`. Scope is `OFFLINE_SOURCE_COPY`; independence is `SELF_REVIEW` or `INDEPENDENT` (different named writer/reviewer required for the latter). Subjects exactly match released contract/copy refs and contract source pins. Verdicts are exactly `source_copy=PASS, editorial=PASS, first_mention=PASS`; reviewed ads match full order; reviewed fields exactly enumerate each ad's `AD/caption` then ordered `AD/CARD.FIELD` in the card-field order above; unresolved findings must be empty. These are revision-bound attestations, not factual proof or buyer/PO content acceptance. |
| Call spec | `schema_version, revision, release, contract, copy, review, calls`. Each call has `call_id, targets, references, concepts, artwork_text, prompt, prompt_sha256, output_id, output_path`. Refs match the coordinator-pinned release. Targets match the exact released group/order/count; call IDs and outputs are unique. |
| Per-card concept / visible text | Each concept has `card_id, concept_id, reader_question, description, props, artwork_labels`, ordered by targets. Props/labels are string lists; labels must equal reviewed labels. `artwork_text` maps each target to only approved artwork fields from copy. IDs/descriptions/props can produce repetition advisories, never creative acceptance or a keyword diversity veto. |
| Prompt | `make_prompt(contract, call)` assembles separately marked style/reference-role/concept/artwork sections. Planned `prompt` must equal this assembly, and `prompt_sha256` hashes its exact UTF-8 bytes. No call-specific free-form suffix can introduce extra printed wording. Nonprinted concepts/constraints still need human judgment and actual-image inspection. |
| Preflight receipt | Generated result: schema/gate version and actual gate-file SHA-256, layer, purpose, raw saved-file input hashes, coordinator release pin, spec identity, all call IDs, optional selected `scope_call_id` (null for initial whole-batch check), advisories, `mechanical_verdict`, `semantic_verdict=NOT_ASSESSED`, `creative_verdict=INSUFFICIENT_EVIDENCE`, `authority=NO_GENERATION_AUTHORITY`. Selected-call receipts cannot check another call. Optional output must be a new JSON file outside inputs and artwork output directory; no receipt hashes itself. |
| Planned dispatch check | Proposal has exactly `schema_version, record_kind, call_id, preflight_sha256, prompt, prompt_sha256, reference_paths, output_path`. `record_kind=PLANNED_DISPATCH_CHECK`. Gate recomputes fresh preflight and compares saved receipt, exact call arguments and receipt-byte hash, then rechecks all inputs. Result explicitly has `actual_dispatch_observed=false`. This is not an executed-call record or a provider integration. |
| Viewer payload check | `viewer-check` accepts only JSON equal to the approved public copy projection. Unknown nested keys, hidden HTML/metadata/attachments serialized into this payload, altered wording and full internal contract serialization fail. This does not inspect arbitrary finished HTML/PDF/native pixels; their export structure and actual wording remain mandatory downstream inspection. |

Use the source/copy/contract/review/release/spec files in that dependency order; review and release reference saved inputs, never themselves. Approved input byte changes invalidate dependent attestations/pins. A trusted release pin is supplied by the authorized coordinator immediately before checks, not discovered from the mutable call spec. Run `dispatch-check` immediately before each actual authorized call; no check bridges unobserved later changes or certifies an unobserved tool invocation.
